# Make diagnostics bounded, read-only, and secret-safe

Release 1 ships `positron doctor` for authenticated online or exclusively locked offline read-only inspection of configuration, storage, keys, catalog, resources, maintenance, operations, listeners, backup, and repositories. Repair remains a separate previewed, idempotent, audited workflow. `positron support bundle create` builds a versioned checksummed archive from a closed typed allowlist containing redacted configuration, identities, health, bounded metrics and logs, metadata summaries, state, environment characteristics, Doctor Report, and sanitized Crash Records. It excludes telemetry, query output, credentials and hashes, private keys, all encryption key material, recovery artifacts, secret values, authorization, raw memory, and cores. Deployment identifiers are pseudonymized with an ephemeral per-bundle mapping unless explicitly retained, and a Redaction Report declares classifications, omissions, truncation, encryption, and signature state. Generation is resource-bounded, supports native age X25519 recipients, and signs manifests when the Instance Integrity Key is available. A plaintext bundle requires an explicit owner-only warning path and is an operator export outside Positron-managed database persistence, never an exception to mandatory encryption for managed persistent objects. The same Rust binary works through native, Docker, and Kubernetes execution, and release tests plant canaries across all subsystems and fail on any prohibited disclosure.
