# Make fencing, hibernation, and deletion explicit lifecycle states

`PositronCluster.spec.lifecycle.mode` supports `Running`, `Fenced`, and `Hibernated`. Fencing is an application state that rejects data and mutation APIs, drains work, durably flushes state, seals active segments, releases mutable storage ownership, and retains only health plus authenticated local inspection and repair. The operator automatically fences ambiguous volume ownership, instance or key mismatch, unsafe upgrade state, and irreconcilable storage identity; unfencing requires an intentional spec change and complete preflight. Hibernation fences before scaling the StatefulSet to zero and retains PVCs, keys, Services, backups, and status while visibly pausing schedules. Deletion defaults to retaining PVCs, repository data, and external keys. Destructive deletion requires a cluster-UID-bound policy, backup and key checks, and audit evidence. Finalizers protect only active transitions, expose blocked conditions, and never delete external KMS keys; Kubernetes Events remain non-secret while durable governance details stay in Positron.
