# Apply bounded declarative Ingest Policy before immutable storage

Each Release 1 Tenant has a versioned declarative Ingest Policy beneath system ceilings. The default preserves every supported field. Deterministic bounded Rust rules may match signal, receiver, namespaced attributes, service identity, severity, or body predicates and may accept, permanently reject, explicitly remove or redact a non-intrinsic field, or explicitly truncate it with a typed marker. Rules cannot rewrite tenant, time provenance, trace or span identity, commit, encryption, or other intrinsic metadata. Evaluation occurs after bounded transport, authentication, Tenant Attribution, and structural decoding but before semantic admission, indexing, persistence, encryption, and acknowledgment, and unredacted matched values never enter Positron-managed output. Each admitted request snapshots one policy generation and every Store Block carries exact Policy Provenance. CLI validation, fixture testing, diff, and explanation precede generation-checked idempotent activation with governance evidence. Changes are prospective only; Release 1 offers no retroactive rewrite, scripting, WASM, webhook, or synchronous external processor. Receiver results and bounded metrics identify policy outcomes without exposing source values, and compatibility claims use the default preserving policy.
