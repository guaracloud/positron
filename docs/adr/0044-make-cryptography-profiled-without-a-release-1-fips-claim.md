# Make cryptography profiled without a Release 1 FIPS claim

Release 1 makes no FIPS 140-3 validation claim. All cryptographic operations pass through one internal Rust Crypto Backend covering authenticated encryption, key wrapping, hashing, signatures, secure random generation, and zeroization. Dependencies are pinned, and each release publishes a cryptographic inventory, SBOM, known-answer results, cross-platform test-vector results, and vulnerability-response policy. Stored algorithm identifiers and the backend boundary permit a future Cryptographic Profile backed by a validated module and compatible recovery and signature constructions, but that profile must define supported operating environments, pass separate release gates, and advertise only the validation status actually held. Approved algorithm names alone never constitute a module or product certification.
