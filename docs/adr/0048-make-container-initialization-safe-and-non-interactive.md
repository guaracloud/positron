# Make container initialization safe and non-interactive

The OCI image invokes the Rust binary directly and defaults to `positron serve --init-if-empty`, using `/var/lib/positron` for data, `/var/lib/positron-secrets` for local keys and bootstrap material, `/etc/positron` for configuration, and `/run/positron` for disposable state. Truly empty data and secrets mounts initialize transactionally, create the default tenant and mandatory encryption hierarchy, and start serving. Initialization resumes only provably incomplete initialization and never treats corrupt or inconsistent state as empty; existing data with missing or mismatched keys and existing key material without its matching instance fail closed. Non-interactive initialization never logs the initial system-administrator API key: owner-only claim material is retrieved once through `positron bootstrap claim` and atomically destroyed, or Helm initializes from an operator-supplied Kubernetes Secret. Docker, Compose, and Kubernetes use the same workflow and retain all key-custody warnings.
