# Bind every artifact to a reproducible, signed, security-supported release

Release 1 uses one signed Release Manifest to bind source, product and API identity, schemas, Compatibility Manifest, every distribution and SDK artifact, digests, pinned toolchains, dependencies, SPDX and CycloneDX SBOMs, licenses, provenance, evidence, and publication state. Functional Reproducible Payloads are verified separately from signing, notarization, timestamp, and registry wrappers. Artifacts receive native provenance and signatures where available, OCI uses immutable transparency-backed digests, and examples never trust mutable tags. `positron release verify` authenticates artifacts offline against an explicitly installed Project Trust Root, bundled proofs, rotation, and revocation state. Known exploitable critical issues block release; scoped exceptions require expiring signed evidence. Unsafe Rust is denied by default and isolated exceptions carry invariants and targeted dynamic verification. Complete conformance, fault, security, recovery, migration, platform, and reproducibility evidence—not compilation—gates publication, and partial registry publication resumes at the same version without announcing completion. Native self-update is excluded, operator auto-update remains opt-in signed patch-only, and a published Security Support Window covers the current and immediately previous minor with coordinated advisory and revocation procedures.
