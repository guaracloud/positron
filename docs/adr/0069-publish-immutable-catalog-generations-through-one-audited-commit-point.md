# Publish immutable Catalog Generations through one audited commit point

Release 1 stores control-plane state as immutable encrypted Catalog Objects and serializes mutation through one Catalog Writer while readers pin immutable Catalog Generations. Telemetry append remains off this path. A transaction synchronizes new objects, reserves the next logical governance-audit position and writes any immutable Prepared Audit Entry, writes an encrypted Catalog Commit Record binding predecessor, roots, object digest, transaction, and audit frontier, then atomically publishes and synchronizes an authenticated commit marker as its sole visibility point. The audit sequencer prevents later records from chaining through a reserved invisible position. Failed publication leaves the prior catalog and governance frontier current, releases the position, and leaves only unreachable transaction-owned evidence; it never truncates an unrelated committed audit record. Every governance-sensitive mutation uses this joint commit. Recovery accepts only the highest complete verified predecessor chain and fences a published generation with missing or unauthenticated state rather than mixing roots. Reference-driven garbage collection respects snapshots, leases, backups, verification, migration, and recovery, while explicit catalog inspection, verification, and offline recovery never synthesize missing state. The logical commit interface permits future consensus ordering without changing objects or Signal Stores, and crash tests prove predecessor-or-successor atomicity at every persistence boundary.


A pre-marker API-key create or rotation may additionally retain an encrypted authenticated prepared record in its transaction-owned staging directory before the immutable `transaction.digest`. The record is not a Catalog generation or public audit outcome. It may publish only when its canonical request digest, exact immutable digest, referenced objects, audit, predecessor generation, and audit frontier all verify. Startup defers only its own unaudited ledger publications while such a record exists, so the owner can resolve the exact predecessor; any other successor leaves the record unavailable. Recovery never replaces the transaction digest or reuses the transaction for changed content, and never reconstructs or redisplays a secret.
