# Ship bounded Operational Telemetry without a Metrics Store

Release 1 database and operator processes expose bounded Prometheus/OpenMetrics, structured logs, Health State, and optional internal OTLP traces independently of the follow-on native Metrics Signal Store. Database metrics cover ingestion, rejection, durability, storage lifecycle, query admission, tails, encryption, providers, backup, restore, and lifecycle; operator metrics cover reconciliation, retries, leadership, conditions, upgrades, backups, fencing, and drift. Labels exclude unbounded tenant and telemetry identities, while authenticated administration APIs provide tenant detail. Non-interactive logs are JSON and redact secrets and telemetry bodies. Optional traces require an explicit external OTLP destination, and self-export is rejected by default. One Health State drives liveness, readiness, degraded detail, Kubernetes conditions, and Events. Releases include operational dashboards, alert rules, ServiceMonitor examples, and runbooks, and never silently store Operational Telemetry as tenant signal data.
