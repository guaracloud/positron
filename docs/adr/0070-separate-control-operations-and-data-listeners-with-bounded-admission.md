# Separate control, operations, and data listeners with bounded admission

Release 1 defines an owner-only non-network Control Listener, a minimal separately bound Operations Listener, and independent `api`, `otlp-grpc`, `otlp-http`, and `loki-push` network roles. Each Network Listener Profile owns binding, TLS and mTLS, Plaintext Opt-Out, proxy trust, connection, request, decompression, HTTP/2, gRPC, keepalive, and timeout limits. Public data binding requires valid TLS unless explicitly opted out. Only minimal health is unauthenticated by default; non-loopback metrics require mTLS, sufficiently scoped API-key authentication, or an explicit visible exception. Kubernetes references Secrets and cert-manager without inventing public trust. Connection Admission bounds address and global resource use before authentication, then Principal and Tenant accounting applies. CORS and credential forwarding default off, forwarded headers require exact trusted peers and fixed hops, and Release 1 has no PROXY protocol auto-trust. Listener reload validates and binds a replacement before draining the old surface. Distribution and real network-abuse tests prove slow-client, TLS, HTTP/2, gRPC, decompression, proxy, rotation, conflict, and drain behavior.
