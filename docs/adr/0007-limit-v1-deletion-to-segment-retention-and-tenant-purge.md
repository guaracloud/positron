# Limit version 1 deletion to segment retention and tenant purge

Retention is configured per tenant and signal store and removes only fully expired sealed segments through an atomic manifest change; new query snapshots stop seeing them immediately, while physical reclamation waits for older snapshots to release them. Version 1 also supports managed-scope whole-tenant purge: it blocks the tenant, removes live data, eliminates every reachable Tenant KEK envelope from the instance and registered Backup Repositories, destroys remaining key material, and prevents managed restores from resurrecting the tenant. Governance audit preserves only purge evidence under system retention. Positron cannot revoke unregistered, exported, or offline copies. Version 1 does not support deleting individual records, identifiers, attribute matches, or arbitrary time slices; targeted deletion would require an explicit rewrite or record-tombstone design outside the initial immutable-storage contract.
