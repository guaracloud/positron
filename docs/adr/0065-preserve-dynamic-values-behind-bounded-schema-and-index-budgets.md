# Preserve dynamic values behind bounded schema and index budgets

Release 1 preserves the supported OTLP value model, separate resource, instrumentation-scope, and record namespaces, cross-record typed variants, and ordered Attribute Occurrence Sets without implicit coercion or last-write-wins behavior. One Value Limit Profile bounds transport expansion, request and record size, bodies and values, attribute counts, keys, nesting, arrays, and key/value lists under hard system maxima and optional lower tenant limits. Exceeding a limit rejects explicitly; only a configured pre-persistence Ingest Policy may transform content. Each Tenant Schema Catalog has bounded entries, memory, storage, and index budget. Valid paths beyond those budgets remain fully typed and explicitly queryable in Schema Overflow without growing catalog, planner, statistics, or automatic-index state. Discovery surfaces bounded summaries and overflow evidence, while Attribute Promotion spends a reversible per-tenant index budget without changing logical results. Mutable catalog state is owned only by the governed tenant schema session; Signals exposes immutable catalog views and opaque staged changes, never an independently constructible writer. Scalar promotion uses a bounded typed-variant dictionary plus canonical per-block coverage bound to the exact Store Block identity and authenticated payload digest. Query-use evidence is applied through that governed session and can install or remove physical coverage. Only semantically verified coverage for a catalog member may prune; stale, missing, unreachable, replaced, demoted, generic, and overflow records retain exact fallback query semantics, including ordered duplicate `index`, `any`, and `all` selection without coercion. The Log Store may additionally retain a bounded UTF-8 byte-trigram summary for string bodies, bound to the same exact block identity and authenticated payload digest, solely to prove substring or mandatory-regex-literal absence. Partial, missing, stale, replaced, generic, and overflow coverage always falls back to authenticated decoding and reports reduced pruning; it never changes search results.

Version 2 Store Blocks remain the authoritative recovery source. The tenant-bound `PSCHEMA1` checkpoint is rebuildable optimization state, published only at quiescent lifecycle points: after bootstrap replay and before Serving when recovery changed it, or during graceful shutdown after ingest drains. Its bounded physical-coverage sidecars and canonical per-shard replay frontiers participate in allocation-free preflight, retained-memory accounting, and persistent-byte limits before decode. Version 3 of `PSCHEMA1` adds explicit per-block framing for the optional text summary; version 1 and version 2 objects remain readable, and any mutation upgrades surviving physical entries before publication. Serving ingest updates the governed live session but never opens the Catalog Writer or waits for checkpoint publication. A crash before publication replays authenticated committed blocks at the next bootstrap; missing or stale optimization state may reduce pruning but cannot omit a result. Signals exposes bounded, immutable, snapshot-bound discovery results with deterministic summaries and sampled path digests. Tenant-administrator pagination is exposed only through the canonical Tenant Attribution, tenant-lifecycle, and administration work in tickets #69 through #71 and the recoverable Durable Operation authority in ticket #73; Runtime defines no schema-local operation or cursor authority and does not substitute system-administrator inspection. CLI, administration, operational metrics, and adversarial receiver tests prove limits, duplicate and type semantics, compression bounds, and policy ordering.
