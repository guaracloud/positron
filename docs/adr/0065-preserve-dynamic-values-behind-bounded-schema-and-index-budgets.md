# Preserve dynamic values behind bounded schema and index budgets

Release 1 preserves the supported OTLP value model, separate resource, instrumentation-scope, and record namespaces, cross-record typed variants, and ordered Attribute Occurrence Sets without implicit coercion or last-write-wins behavior. One Value Limit Profile bounds transport expansion, request and record size, bodies and values, attribute counts, keys, nesting, arrays, and key/value lists under hard system maxima and optional lower tenant limits. Exceeding a limit rejects explicitly; only a configured pre-persistence Ingest Policy may transform content. Each Tenant Schema Catalog has bounded entries, memory, storage, and index budget. Valid paths beyond those budgets remain fully typed and explicitly queryable in Schema Overflow without growing catalog, planner, statistics, or automatic-index state. Discovery surfaces bounded summaries and overflow evidence, while Attribute Promotion spends a reversible per-tenant index budget without changing logical results. Mutable catalog state is owned only by the governed tenant schema session; Signals exposes immutable catalog views and opaque staged changes, never an independently constructible writer. Scalar promotion uses a bounded typed-variant dictionary plus canonical per-block coverage bound to the exact Store Block identity and authenticated payload digest. Query-use evidence is applied through that governed session and can install or remove physical coverage. Only semantically verified coverage for a catalog member may prune; stale, missing, unreachable, replaced, demoted, generic, and overflow records retain exact fallback query semantics, including ordered duplicate `index`, `any`, and `all` selection without coercion.

Version 2 Store Blocks remain the authoritative recovery source. The tenant-bound `PSCHEMA1` checkpoint is rebuildable optimization state, published only at quiescent lifecycle points: after bootstrap replay and before Serving when recovery changed it, or during graceful shutdown after ingest drains. Its bounded physical-coverage sidecars and canonical per-shard replay frontiers participate in allocation-free preflight, retained-memory accounting, and persistent-byte limits before decode. Serving ingest updates the governed live session but never opens the Catalog Writer or waits for checkpoint publication. A crash before publication replays authenticated committed blocks at the next bootstrap; missing or stale optimization state may reduce pruning but cannot omit a result. Administration exposes a governed, bounded, snapshot-bound paginated discovery operation with deterministic summaries and sampled path digests; it exposes no mutable catalog reference. CLI, administration, operational metrics, and adversarial receiver tests prove limits, duplicate and type semantics, compression bounds, and policy ordering.
