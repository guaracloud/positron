# Use scoped API keys for Release 1 governance

Release 1 authenticates principals with API keys persisted only as salted hashes and authorizes fixed ingest, query, tenant-administration, or system-administration scopes. Interactive initialization may display one system-administrator secret once, while non-interactive initialization exposes it only through an owner-only one-time Bootstrap Claim that is atomically destroyed when claimed. Tenant keys can overlap for rotation and be revoked immediately, and the CLI manages their lifecycle without redisplaying secrets. Built-in passwords, browser sessions, SSO, identity federation, and customizable RBAC are deferred; deployments may use an authenticating proxy while Positron records security and administrative activity as governance audit records.
