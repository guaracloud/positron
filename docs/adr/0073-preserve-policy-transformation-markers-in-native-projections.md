# Preserve policy transformation markers in native projections

Release 1 represents policy-created removal and redaction as payload-free typed markers and represents truncation as a marker retaining only a sanitized native value of the original kind. Markers remain visible through existing internal projections at their original paths and slots: redaction and removal marker leaves have no descendants, duplicate occurrence order and count and array indices are preserved, marker values never satisfy ordinary native scalar, Null, native-kind, or original-kind predicates, `any` and `all` treat them as nonmatching, and `index` retains ordinal positions; truncation keeps normal same-kind comparison and projection over its sanitized value, including exact fallback behavior. A truncation marker's immediate child must be an ordinary same-kind root value, while marker leaves contained inside a retained Array or key/value-list child remain valid and preserve their own policy evidence. No removed or redacted source bytes, value, length, hash, or rendering is retained; only the marker action and original native kind are allowed. Only the shared Ingest Policy transition may create markers, producer candidates cannot forge them, and marker metadata and retained slots are bounded and charged to value-size, memory, and reservation budgets; marker-only paths do not infer schema scalar types or dictionaries, and unsafe coverage falls back to generic scanning. Log and Trace Store writers therefore emit a distinct marker-capable version 3 for all new blocks with strict action and original-kind validation, while v1 and v2 native tags `0..=7` remain readable with their existing meaning and no null-sentinel reuse, schema-sidecar version change, new query syntax, or public v1 endpoint.
