# Stream stable Query Snapshots through bounded resumable batches

Release 1 query responses contain a typed header, deterministic Result Batches, and one mandatory terminal status. Cursor pagination requires a total order and uses opaque authenticated Query Cursors bound to Tenant ID, plan and parameters, API version, Query Snapshot, cumulative Query Budget, last key, Snapshot Lease, and expiry rather than numeric offsets. Bounded persistent Snapshot Leases pin required immutable objects under tenant quota and survive restart without delaying Tenant Purge. Budgets accumulate across pages and reconnects. Each batch has a deterministic sequence and digest; ambiguous reconnect may repeat the last batch with the same identity, allowing CLI and Generated SDK helpers to deduplicate without gaps. Resume never switches snapshots, and expiry, authorization change, quarantine, or reclamation is explicit. `Complete` appears only after all work and batches finish, with a terminal Result Digest over the logical output. Large exports use the same contract as a bounded Durable Operation with a signed manifest. Release tests cover interruption, restart, rotation, tampering, lifecycle races, integrity failure, authorization change, and cumulative limits.
