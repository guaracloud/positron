# Bind every data request to one tenant and forbid impersonation

Release 1 performs Tenant Attribution from a bearer API key before payload decoding, query planning, or resource admission, resolving exactly one Principal, Scope, and tenant for data-plane work. OTLP attributes, Loki labels, paths, request bodies, and compatibility headers cannot select a tenant. A supported hint such as `X-Scope-OrgID` may be absent or must match an immutable protocol-specific External Tenant Alias for the authenticated Tenant ID; conflicts and mixed-tenant batches are rejected before commit. System-administrator principals cannot ingest, query, tail, federate, or impersonate tenant traffic. Grafana data sources and automation use explicit tenant-bound query principals. Trusted proxies still authenticate with a Positron API key, and forwarded identity supplies only redacted Proxy Actor Context without changing authority. mTLS remains transport identity only. Failure responses do not enumerate credentials or tenants, aliases are never reused after purge, and every receiver conformance suite proves these boundaries with forged, conflicting, revoked, wrong-scope, suspended, and purged cases.
